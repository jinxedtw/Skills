# Android 页面截图图册

还需要用户输入要保存到的目录

输出一个文件夹到用户指定目录，文件夹名称就是，app名称-grallery，

## 输入与交付目录

- 从本次用户请求读取保存目录；没有提供时，先询问“请提供图册要保存到的目录”，收到答案后再开始截图。不要复用其他任务的目录，也不要自行选择桌面。
- 从当前工程、设备安装包或用户说明确认 App 的显示名称。最终输出为 `<用户指定目录>/<app名称>-grallery/`。后缀固定为 `-grallery`，不要改成 `-gallery`。
- 文件系统不允许的名称字符可替换为 `_`，保留应用原显示名称作为图册标题，并告知文件夹名的替换。同名目录已存在时，先问用户覆盖、换名或另选目录；仅在用户明确选择覆盖后使用 `--overwrite`。
- 默认手动调用；不要更改应用业务逻辑来配合截图。

## 采集

1. 检查工程现有修改、页面路由、清单中的 Activity 和已有截图测试。按实际可达流程建立页面清单，包含主要弹窗、空状态、有内容状态、处理前后及保存前后。格式和模式共用页面时，覆盖有明显差异的参数状态。
2. 确认可用设备与应用版本。用当前工程构建时，保留用户改动，安装使用保留数据的方式。发现多个设备且无法确定目标时先询问。
3. 先验证一张应用截图：设备已解锁、目标 App 在前台，截图不是锁屏、黑屏、启动遮罩或其他应用。锁屏需要用户解锁，切到其他应用需要恢复目标 App；不要将这些图片收入图册。采集期间可仅为被测 Activity 添加 `FLAG_KEEP_SCREEN_ON`。
4. 优先复用并适配现有 instrumentation；也可通过 ADB/受支持的 UI 自动化操作。使用专用样例，避免带入用户私人图片。记录截图对应的页面、状态、应用版本、设备及界面语言。
5. 在动历史、偏好、剪贴板或数据前，将原值持久化到截图目录之外的备份。用 `finally` 恢复；进程被终止时从备份恢复后再重跑。只清理本次生成的样例和导出文件，不清空用户资料。不点击提交反馈、购买、恢复购买或删除用户内容。
6. 每成功一张就更新 `manifest.json`，不要等全部结束才写。截图失败单独记入问题清单；排除不合格图片，补拍缺失状态。对未知界面不要盲目发送返回键，以免退出目标流程。

遇到启动等待、输入注入或二进制导出问题时，读取 [reference.md](reference.md)。采集代码依赖当前 App 的包名、控件和路由，不能把其他工程的测试类直接套用。

## 页面清单

采集临时目录放原始 PNG 和 UTF-8 `manifest.json`。清单是数组，每条形如：

```json
{"file":"home.png","title":"首页","category":"开始与导入","note":"实际显示的状态","width":1080,"height":2376}
```

`file` 只用唯一的 PNG 文件名，不带目录。尺寸由生成脚本从 PNG 读取。中文标题可以对应其他界面语言；不要把英文页面声称为中文页面。用户要求的范围中无法访问、已废弃或加载失败的页面，在图册说明中明确列出。不要用旧图或合成图冒充本次真机截图。

## 生成与核对

脚本基于 Node.js 内置模块；Windows 总览脚本另外使用 PowerShell 和 System.Drawing。以下 `<skill目录>` 指本技能所在目录，`<采集目录>` 是临时 PNG 清单目录，`<保存目录>` 必须来自用户。

```powershell
node "<skill目录>/scripts/build-gallery.cjs" --screens "<采集目录>" --output "<保存目录>" --app-name "<app名称>" --date "YYYY-MM-DD" --device "<实际设备与系统>" --language "<实际界面语言>" --exclusions "<未收录范围与加载问题>"
& "<skill目录>/scripts/create-contact-sheet.ps1" -GalleryDirectory "<保存目录>/<app名称>-grallery"
node "<skill目录>/scripts/verify-gallery.cjs" "<保存目录>/<app名称>-grallery"
```

- 日期使用用户所在时区。脚本不设置默认保存目录；缺少必需参数会报错。
- `index.html` 内嵌原始 PNG，可单独复制、离线打开，支持分类、搜索、点击放大和方向键翻页。
- 图册文件夹包含 `index.html`、`screenshots/*.png`、`screenshots/manifest.json`、`metadata.json`、`contact-sheet.jpg` 和 `使用说明.txt`。非 Windows 环境可以用可用的图像库生成同名总览，不要为此更改系统配置。
- 验证脚本核对内嵌图片与原始文件一致，并测试分类、搜索和大图处理器；这不等于完整浏览器测试。还需查看总览及代表性原图，条件允许时在浏览器检查实际布局。遵守浏览器访问限制，不绕过被拒绝的 URL 或权限。
- 最终按页面清单核对覆盖范围，说明实际数量和重要缺失；提供绝对路径的图册链接。不要把“若干主要页面”声称为“所有页面”。
